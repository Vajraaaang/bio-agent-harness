# Private and clinical handoff

Treat filenames, paths, column names, free text, outcomes, axes, statistics and plots as potentially identifying. Keep private/clinical material and PartitionVault-embargoed content out of model prompts, MCP arguments, logs, error details, UI resources and remote tools. Use only opaque handles and generic handoff status already returned by the control plane. Never request data excerpts to diagnose a refusal.

Classification is sticky across aliases, derivatives, prior public registrations and mixed sessions. When private material enters a session, follow local handling for the entire affected lineage. Hiding a column, changing a filename or hashing a path cannot authorize disclosure.

Use the supplied local handoff to Companion Studio with `--offline-only`. The operator admits inputs, inspects fields, binds exact permissions and reviews the plan locally. Keep browser launch opt-in. For Tier 2, author a schema-blind template against synthetic fixtures and placeholders first. Bind local fields, data and outputs only inside offline Studio after review. Do not return the binding, diagnostics or fitted results through MCP.

A handoff establishes custody only. Report the local action still required using bounded status, or abstain if the offline route is unavailable. Keep `clinical_release_allowed = false` for every receipt and package.
