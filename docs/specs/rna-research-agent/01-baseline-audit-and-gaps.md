## Executive Baseline Verdict

`bio-agent-harness` already contains substantial, genuinely useful scientific-governance infrastructure — notably SQLite WAL custody ([scientific_authority.py](../../../src/devbench/engine/scientific_authority.py), [workflow_operations.py](../../../src/devbench/engine/workflow_operations.py)), `COUNT-1` raw-count ancestry gating, rank/confounding refusals ([contrast_design.py](../../../src/devbench/core/contrast_design.py)), content-addressed execution receipts, private/clinical data isolation ([permissions.py](../../../src/devbench/engine/permissions.py)), cross-aim DAG invalidation ([thesis_aims.py](../../../src/devbench/platform/thesis_aims.py)), and digest-pinned OCI container execution ([mounted_kernel_oci.py](../../../src/devbench/engine/mounted_kernel_oci.py)).

However, evaluated under the specification's **Four-Level Claim Hierarchy** (`L1: Execution Verified` | `L2: Statistically Calibrated` | `L3: Scientifically Supported` | `L4: Clinically Validated [Held / Out of Scope]`):

1. **Zero of 20 provisional problem families achieve full `L2` or `L3` validation** across open biological regimes. The execution release gate (`make test-rna-release`, [verify_rna_execution_release.py](../../../scripts/verify_rna_execution_release.py)) passes only **9 of 39 registered question contracts** (`L1` synthetic execution) and remains **blocked on 30 of 39** ([execution-release-gate.md](../../../docs/audits/2026-11-23-rna-capabilities/execution-release-gate.md)).
2. **Core differential expression calibration fails its own frozen gate**: across 2,200 synthetic cohorts (`arm64` + `amd64`), 3 of 5 `edgeR` quasi-likelihood regimes exceed the 7.5% null-FDR ceiling (**B-I 9.0%**, **S-I 10.5%**, **S-P 8.0%**), and cross-architecture p/q-value drift (`3.06e-6` / `4.40e-6`) exceeds the `1e-10` tolerance.
3. **Severe architectural fragmentation blocks generality**: two disconnected MCP servers ([plugin_mcp.py](../../../src/devbench/platform/plugin_mcp.py) vs [server.py](../../../src/devharness_server/server.py)), **5 implemented kernel/core capabilities** with zero direct references/queuing in `plugin_mcp.py` or `plugin_graph.py` (§4.1), a 5,805-line monolithic `Plan` union hardcoding dataset-specific motor-neuron operations, a manual Studio UI click bottleneck on bulk/pseudobulk DE fits, rigid size/concurrency/timeout ceilings (`100 MB` CSV-only local solvers, `100 MiB` H5AD checks, `4,096` samples, global 1-job mutex, 1-hour `SIGALRM`), and zero live-agent or external benchmark evaluations.
4. **PR #13 (`ad1d7472..18161fd`) materially improved several solvers** (beta-binomial QL DTU, spatial adaptive radius and depth residuals, Milo-style refinement and TMM offsets, cross-fitted perturbation efficacy, `fgsea`/`decoupleR` signed `-log10(p)` ranking, missing-mito `NaN` handling, unbalanced `dream`, private H5AD streaming) — **while introducing new regressions/drift at HEAD** (spatial `cell_type` MCP preflight crash, stale payload contract docs, private-only H5AD size bypass, and stale v0.1.0 Codex validation artifacts).

## 2. Complete Capability & Lifecycle Status Matrices (HEAD `18161fd`)

To avoid conflating software smoke execution with scientific validity, every row strictly separates four status dimensions:
- **Implemented (`L1` code exists)**: Runnable solver/orchestration module exists in `src/`.
- **Scientifically Validated (`L2` / `L3`)**: Independent statistical calibration across realistic nulls/alternatives (`L2`) and/or real-world multi-cohort benchmark reproduction (`L3`).
- **Partially Supported**: Covers only a narrow subset of the biological scope, assay modalities, or workflow mechanics.
- **Missing**: Absent from runtime execution (at most an answerability refusal contract in [rna_answerability.py](../../../src/devbench/core/rna_answerability.py)).

Cross-references map each provisional v1.0 Family (`#1`–`#20`) to the revised **Orthogonal 3-Axis Capability Model** (`Axis A`: `A0` Storage/Upstream, `A1` Donor Forensics, `A2` Modality QC/Artifacts, `A3` Modality/Biotype Qualifiers; `Axis B`: `B1`–`B12` + `B_OPEN`; `Axis C`: `C1`–`C2`) in [02-problem-space-and-methods.md](02-problem-space-and-methods.md), and each provisional Stage (`A`–`L`) to the **Epistemic Investigation Graph** (`E0`–`E6` + `E_ABSTAIN`) in [03-adaptive-research-design.md](03-adaptive-research-design.md).
