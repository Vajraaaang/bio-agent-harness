# Projects, dataset attachments and retained history

Projects are now real protected service workspaces, selected per authenticated request rather than through global mutable server state. Creation allocates separate private records, data and actor directories. Each project owns its chats, plans, jobs, scientific store and draft attachments. Switching saves the current draft and performs a full authenticated page bootstrap; scientific deep links retain project identity. All projects share one execution worker.

The picker supports creating a project and optionally copying an authorized local input into its data directory. More inputs can be added explicitly from the configured local-file library. Copies are bounded, descriptor-relative and hash-checked; the source remains unchanged. The current limits are 20 projects, 64 data entries per project and 128 MiB per imported file. This is an authorized local-file library, not arbitrary host-filesystem access or remote upload.

Earlier projects are retained read-only. Their original source epoch serves their existing settings and artifacts through a bounded private loopback compatibility reader. The current UI does not reinterpret or rewrite frozen execution settings. Only workspace display metadata and input inspection remain writable; analysis/model actions are disabled both at startup and the parent HTTP boundary. Safe notebook HTML downloads remain attachments, never active previews.

Analysis history is visible whenever records exist and includes every retained job within the service's existing 100-job bound. Failed, interrupted and unreviewed states remain visible. The chat list collapses independently, and the icon-only New chat action remains available outside it.

A chat can attach up to eight project datasets. Single-source requests retain their existing API; multiple-source requests bind the exact ordered set of original files, hashes, observed profiles and per-file declarations. Drafts and follow-ups retain all attachments. Inspecting a file does not replace the attached set, and missing restored files block submission rather than silently selecting another input.

Multiple inputs use the scientific workflow and a typed immutable input-set contract. The actual planning graph receives every named artifact. It never substitutes first-file QC for joint analysis. Cross-file feature alignment, identifier collisions, measurement compatibility and biological independence remain unknown until assessed. Compatible trial methods must accept the full artifact set.

The local launch uses a supported supplied-evidence-only scientific runtime. Authorized model planning can advance through audit, question, discovery and candidate generation, then stops for a substantive scientific reviewer. No reviewer identity, review evidence, trial or integration result is fabricated. A built-in multi-file concatenation engine was not added; joint numerical execution still requires an appropriate reviewed compatible method. Registered scientific sources retain their existing 100 MB per-source ceiling.

Expanded evidence now uses full-width nested records instead of recursively shrinking columns. Scroll regions are keyboard-focusable, long values wrap, and full JSON remains available. Actual browser inspection at the 300px minimum chat width found equal body/client widths and readable `scrna` values. Native pickers remain bounded by the viewport.

The five scientific questions now share one compact rounded analysis card: Data, Question, Methods, Results and Conclusion. Native expandable rows retain the full questions as accessible labels. Required actions open their section when newly required; user expansion choices and draft edits survive refreshes. Earlier questions remain in separate collapsed context. The layout uses the workbench's existing monochrome type, 40px rows and 14px card radius, with no copied reference actions or fabricated progress. Browser checks found five current sections, no numbered headings, and no horizontal overflow at a 300px chat width.

Verification reports, source epochs, browser evidence and two independently generated synthetic 80-cell/60-gene datasets are retained in `reports/workbench-projects/2026-10-28/`. The initial broad run and its outdated-fixture failures remain preserved alongside corrected rechecks. No live model response, joint numerical analysis or clinical qualification was established by these platform checks.

The final project/input/compatibility verification passed 414 checks. The final workflow-card and host-integration verification passed another 127 checks. Counts overlap earlier runs; they are not a claimed single full-suite total. Initial failures arose from stale fixtures passing coordinator-generated integration provenance back as a parameter override and from obsolete text-label assertions. Those fixtures were corrected without relaxing the provenance guard, and all failing cases were rechecked.
